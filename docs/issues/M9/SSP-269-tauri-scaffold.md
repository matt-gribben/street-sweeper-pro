# SSP-269: Wrap dist/ in a Tauri 2.12.3 desktop shell (ADR, src-tauri/, scripts)

**Milestone:** [M9 Desktop & Extra Modes](../README.md#m9) · **Type:** feature · **Size:** M · **Areas:** build, platform, tooling, docs

## Summary

Add @tauri-apps/cli 2.12.3 and a src-tauri/ project that loads the unchanged Vite dist/ in a native webview, so later issues can produce macOS and Windows bundles. Record the new top-level directory, the storage decision, the webview-origin and identifier stability rules, and the toolchain pins in an ADR.

## Context

Pins: TECHNICAL_DESIGN §1.1 and ADR 0001 pin `@tauri-apps/cli` **2.12.3** (currently labelled 'Desktop wrapper (M9, deferred)'). All npm deps are exact (no ^ or ~), npm only, and `package-lock.json` is the only JS lockfile (CLAUDE.md hard rule 6). The ROADMAP M9 checklist explicitly calls for this dependency. The Rust crates are new dependencies, so they get recorded in the ADR below.

Facts: Vite config uses `base: './'` and outputs `dist/` with hashed JS/CSS. `public/assets/**` is copied verbatim and runtime URLs resolve relative to `import.meta.env.BASE_URL` (TECHNICAL_DESIGN §20.2), so dist/ should load from Tauri's custom protocol with no code changes. `dev` = `vite` (TECHNICAL_DESIGN §20.1). The docs don't name a port: 5173 is Vite's default. Tauri's `devUrl` needs a fixed port, so set `server.port: 5173` and `server.strictPort: true` in vite.config.ts. That is a build-config change, not a gameplay change. Playwright's webServer uses `npx vite preview --port 4173 --strictPort` and must keep working.

New top-level directory: TECHNICAL_DESIGN §2 says 'The layout is canonical. New top-level directories need an ADR.' `src-tauri/` is new, so write `docs/adr/0003-tauri-desktop-wrapper.md`. That is the next free number (0001 and 0002 exist). Copy the header table format from ADR 0001/0002 (Status, Date, Deciders, Supersedes, Related).

Storage conflict (resolve in the ADR): ROADMAP M9 says 'Save data goes through the same `localStorage` keys inside the webview' (`ssp.save.v1`, `ssp.settings.v1`; CLAUDE.md §5.1 allows only these two keys). TECHNICAL_DESIGN §16 ends with 'the Tauri store adapter implements the same two-method interface (`read(key)`, `write(key, json)`)'. Default: follow the ROADMAP (plain webview localStorage, zero gameplay code changes) and rewrite that §16 sentence to match. A store adapter stays a fallback only, used if persistence fails in the platform parity checks.

Webview storage is scoped to the app identifier and the webview origin. Tauri 2 serves the frontend from `tauri://localhost` on macOS and from `http://tauri.localhost` on Windows by default, and the Windows `useHttpsScheme` window option switches it to `https://tauri.localhost`. Changing the bundle `identifier` or that scheme after a public release orphans players' saves. Verify both against 2.12.3, and record in the ADR the rule that they never change after the first public desktop release.

Decide these, and record them in the ADR and in TECHNICAL_DESIGN §1.1:
- Rust toolchain version and `tauri`/`tauri-build` crate versions compatible with CLI 2.12.3. Pin crates with `=` in Cargo.toml, commit `Cargo.lock`, and add `rust-toolchain.toml` with the exact channel.
- The bundle `identifier`: reverse-DNS, no trademarks.
- npm script names. Proposed: `desktop:dev` → `tauri dev`, `desktop:build` → `tauri build`.
- Window size. Proposed: 1440×810 (3× of the 480×270 base), resizable, minimum 960×540 (2×). `render/upscale.ts` already computes the integer scale `floor(min(winW / W, winH / 270))` (TECHNICAL_DESIGN §12.1).
- Whether `src-tauri/gen/schemas` (generated by the Tauri 2 CLI) is committed or git-ignored.

Expected tauri.conf.json essentials (Tauri 2 schema; verify against 2.12.3):
- `productName` 'Street Sweeper Pro', with `version` single-sourced from package.json (e.g. `"../package.json"`).
- `build.frontendDist: "../dist"`, `build.devUrl: "http://localhost:5173"`, `build.beforeDevCommand: "npm run dev"`, `build.beforeBuildCommand: "npm run build"`.
- One window titled 'Street Sweeper Pro'.
- A minimal `capabilities/default.json` granting no plugin permissions.
- No `@tauri-apps/api` import.

Icons and IP hygiene: `tauri build` needs the files that `bundle.icon` lists. Don't commit Tauri's default logo icons (hard rule 7). Hard rule 4 also forbids committing a binary without its source. So the placeholder must be produced by a committed, re-runnable command from a committed text source. Example: a flat square of palette index 15 sweeper_yellow with an index-00 outline, generated by a tiny forge step or a Node script using pngjs (already a dependency). Document the command in the ADR. The real icon comes in `SSP-270`.

## Scope

- Add `"@tauri-apps/cli": "2.12.3"` (exact) to devDependencies and update package-lock.json
- Create src-tauri/: tauri.conf.json, Cargo.toml with `=`-pinned crates, Cargo.lock, rust-toolchain.toml, build.rs, src/main.rs + src/lib.rs as Tauri 2 generates them, capabilities/default.json, all loading ../dist
- Fix the Vite dev port (5173, strictPort) so `devUrl` is stable
- Add npm scripts for desktop dev and build (proposed `desktop:dev`, `desktop:build`)
- Add `src-tauri/target/` to .gitignore (and gen/ if it's not committed), and exclude src-tauri build output from Biome and tsc
- Placeholder Kerbside-32 app icon generated by a committed command from a committed source, at the paths tauri.conf.json `bundle.icon` references (no Tauri logo)
- Write docs/adr/0003-tauri-desktop-wrapper.md: src-tauri/ layout, the localStorage-in-webview decision vs the TECHNICAL_DESIGN §16 store-adapter line, Rust and crate pins, the identifier and webview-scheme stability rule
- Update TECHNICAL_DESIGN §1.1 (Rust and crate pins; drop 'deferred'), §2 (layout tree and the .gitignore line), §16 (desktop storage sentence), §20.1 (scripts) and §20.3, plus the README tech-stack table and CLAUDE.md §4.2

## Out of scope

- Release bundles per platform (.dmg, NSIS/MSI, AppImage): see SSP-272, SSP-273, SSP-274
- Code signing and notarisation (SSP-271)
- Final app icon art (SSP-270)
- Any change under src/, tests/ or public/assets/ (no gameplay code changes)
- A Tauri store plugin or @tauri-apps/api usage, unless the ADR justifies it

## Acceptance criteria

- [ ] package.json lists @tauri-apps/cli at exactly 2.12.3 with no ^ or ~, and `npm ci` succeeds from a clean checkout
- [ ] `npx tauri --version` prints `tauri-cli 2.12.3`
- [ ] `npm run desktop:dev` (or the chosen name) opens a native window that boots to TitleScene and can start and drive a Puddle Lane shift
- [ ] `npm run desktop:build` on the dev Mac produces an .app that boots to TitleScene from the bundled dist/ with networking disabled
- [ ] The PR changes no files under src/, tests/ or public/assets/ (`git diff --stat main -- src tests public` is empty)
- [ ] Cargo.toml pins the tauri crates with `=`, Cargo.lock and rust-toolchain.toml are committed, and the Rust and crate versions are recorded in TECHNICAL_DESIGN §1.1
- [ ] docs/adr/0003-tauri-desktop-wrapper.md exists with Status Accepted and records the storage decision, the identifier, and the webview-scheme stability rule. TECHNICAL_DESIGN §16 no longer contradicts ROADMAP M9
- [ ] Every file under src-tauri/icons can be regenerated by the documented command from a committed source. No Tauri logo or other third-party brand image is committed
- [ ] `npm run ci` still passes (lint and typecheck ignore src-tauri/target), and `npm run test:e2e` still starts its preview server on 4173

## Verification

- npm ci && npx tauri --version
- npm run desktop:dev (manual: title screen, start a Puddle Lane shift)
- npm run desktop:build && open src-tauri/target/release/bundle/macos/*.app
- git diff --stat main -- src tests public
- npm run ci
