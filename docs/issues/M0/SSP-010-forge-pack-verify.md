# SSP-010: Add deterministic atlas packing, generated assets.ts, asset-hashes.json and forge verify

**Milestone:** [M0 Foundations & Look Spike](../README.md#m0) · **Type:** feature · **Size:** L · **Areas:** tooling, assets · **Vertical slice**

## Summary

Pack built frames into the `actors` and `items` atlases with JSON, and generate the typed `src/gen/assets.ts` and `public/assets/asset-hashes.json`. Implement `forge verify` (byte and `--pixels` modes) so `npm run assets` and `npm run assets:verify` work end to end.

## Context

Pulled forward from M1 (agreed deviation; record it in the PR and tick it from the M1 checklist later). ROADMAP M1 lists `forge/pack.py` (deterministic maxrects, world + actors atlases) and FRAME generation, but M0's spriteBatch needs per-instance frame rects from the Blender build. Implement it to the §9.3 spec now, so M1 only adds the `world` atlas:
- deterministic maxrects;
- inputs sorted by area descending, then frame id;
- no rotation, 1 px padding, atlases at most 2048x2048.

M0 atlases: `actors` (Bessie, brush, pedestrian) and `items` (lamp-post slices, added later). An atlas with no frames is not emitted.

Atlas JSON `public/assets/atlas/<name>.json`: `{ frames: { "<frameId>": { x, y, w, h, px, py } }, swaps: {} }`.

`src/gen/assets.ts`:
- header exactly `// GENERATED by forge build. Do not edit. Source: assets-src/manifest.json` (ASSET_PIPELINE §9.3; TECHNICAL_DESIGN §21.3 words it slightly differently, so use the §9.3 form);
- then `export const FRAME = { "veh.sweeper:body:h00:0": { atlas: "actors", x, y, w, h, px, py }, ... } as const; export type FrameId = keyof typeof FRAME; export type AssetId = "veh.sweeper" | ...;`
- it must pass the repo tsconfig and be excluded from Biome formatting.
Generated outputs (public/assets/**, src/gen/assets.ts, asset-hashes.json) are committed and written only by `npm run assets`.

`public/assets/asset-hashes.json` maps every generated file path to its SHA-256, sorted by key.

`forge verify` (§5.2/§5.3):
- run `forge build --out build/tmp/verify/`, and run the audio and level tools with `--out` under the same temp root (they are M0 input-count guards, see SSP-006);
- byte-compare every file in asset-hashes.json and src/gen/assets.ts, plus any generated file not listed;
- exit non-zero with a per-file report.
`--pixels` decodes mismatching PNGs, compares RGBA and reports "pixels identical, bytes differ" versus real diffs (JSON/TS are still byte-compared). D-12 needs this.

## Scope

- tools/forge/forge/pack.py (deterministic maxrects per §9.3)
- Emit public/assets/atlas/actors.{png,json} (and items when it has frames)
- src/gen/assets.ts generation (FRAME, FrameId, AssetId)
- public/assets/asset-hashes.json
- forge verify with --pixels
- Run `npm run assets` and commit the generated outputs together

## Out of scope

- forge lint and forge sheets (SSP-011)
- world/ui/fx atlases and procedural tiles (M1+)
- Swap tables (M4)
- verify in ci.yml (M4)

## Acceptance criteria

- [ ] `npm run assets && git status --short` shows no diff after the outputs are committed
- [ ] `npm run assets:verify` exits 0 on a clean checkout
- [ ] Changing one byte of public/assets/atlas/actors.png makes `npm run assets:verify` exit non-zero, naming that file (checked, then restored)
- [ ] Re-encoding actors.png with different zlib settings (same pixels) makes `forge verify --pixels` report 'pixels identical, bytes differ' for that file
- [ ] src/gen/assets.ts contains exactly 192 frame IDs (64 veh.sweeper + 128 veh.sweeper_brush) and `npm run typecheck` passes
- [ ] A test file using `FRAME['veh.sweeper:body:h07:0']` type-checks and `FRAME['veh.sweeper:body:h99:0']` fails to compile (a @ts-expect-error test)
- [ ] Two clean builds give byte-identical atlas PNG/JSON (pytest)
- [ ] `uv run --project tools/forge pytest` passes

## Verification

- npm run assets
- git status --short
- npm run assets:verify
- uv run --project tools/forge python -m forge verify --pixels
- npm run typecheck
- uv run --project tools/forge pytest
