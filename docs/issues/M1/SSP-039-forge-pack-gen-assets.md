# SSP-039: Add the world atlas with 1 px tile/facade extrusion and confirm npm run assets runs end to end

**Milestone:** [M1 Drivable Bessie](../README.md#m1) · **Type:** feature · **Size:** S · **Areas:** tooling, assets, render · **Vertical slice**

## Summary

Extend SSP-010's packer so manifest entries with `atlas: world` pack into `public/assets/atlas/world.{png,json}`. Ground tile and facade frames are extruded by 1 px so tiling surfaces never show seams. Also confirm that the `npm run assets` chain passes end to end in M1. SSP-010 owns the packer, src/gen/assets.ts, asset-hashes.json and forge verify; this issue adds only the world atlas.

## Context

Packer owner: SSP-010 (M0) already implements tools/forge/forge/pack.py to the ASSET_PIPELINE §9.3 spec. It uses deterministic maxrects, sorts inputs by area descending then frame id, never rotates, caps atlases at 2048x2048 and emits no empty atlas. It also generates the atlas JSON (`frames` + `swaps`), `src/gen/assets.ts` (header `// GENERATED by forge build. Do not edit. Source: assets-src/manifest.json`, FRAME, FrameId, AssetId), `public/assets/asset-hashes.json` and `forge verify`. Do not re-implement any of these. Extend them.

What is new here (ART_BIBLE §14.6, the ASSET_PIPELINE §9.3 atlas table):
- `world` holds tiles, roofs, facades and stains. Frames are routed by the manifest entry's `atlas` field; the §6.1 example `tile.asphalt` has `atlas world`. M0 only had `actors` and `items`.
- Ground tiles and facade modules are extruded by 1 px. Edge pixels are duplicated (this is not a transparent gutter), so tiling surfaces never show transparent seams (ART_BIBLE §14.6).
- Record this contract in ASSET_PIPELINE §9.3: the atlas JSON rect `{x, y, w, h}` of an extruded frame covers only the interior cell, never the duplicated border. groundLayer and cityMesh (SSP-045) then sample inside the border with no special case.
- ART_BIBLE names only ground tiles and facade modules for extrusion. Roof surfaces also tile across footprints (16 px/m, aligned to the tile grid, ART_BIBLE §9.5), so ask the lead in the PR whether `roof.*` should be extruded too, and record the answer.
- The repo has no world frames until SSP-040 (tiles) and SSP-041 (facades and roofs), so prove the path with a pytest fixture manifest. An atlas with no frames is still not emitted.

The 1 px transparent gutter for actors, items and fx, trimming, the fill-ratio report and the 2048 overflow error belong to SSP-113 (M4). Do not add them here.

`npm run assets` = `forge build && npm run audio && npm run levels` (ASSET_PIPELINE §5.2). SSP-006 (M0) already made the audio and levels tools input-count guards. With zero sources they log '0 sources; nothing to render' and exit 0. With any source present they exit non-zero ('not implemented until M5' or 'M1'). They accept `--out`. No audio-tool change is needed: this issue only confirms the chain passes. If it does not, fix the guard rather than adding a new mechanism.

PNGs must stay byte-identical across runs (Pillow, no metadata, fixed encoder parameters; CLAUDE.md §5.2). Adding the world atlas must not move any actors or items frame, so the lean_quadrants and scale_1440 goldens stay unchanged.

## Scope

- tools/forge/forge/pack.py: emit the `world` atlas for manifest entries with `atlas: world`, reusing SSP-010's packer, JSON writer, assets.ts generation and hashes generation
- 1 px extrusion (duplicated edge pixels) for `tile.*` and `facade.*` frames; the atlas JSON rect covers the interior cell only
- Record the extrusion rule and the interior-rect contract in ASSET_PIPELINE §9.3
- pytest in tools/forge/tests/test_pack.py: a fixture tile entry packs into world; the border equals the edge pixels; the rect excludes the border; two packs are identical; no empty world atlas is emitted
- Run `npm run assets` end to end and confirm it passes with SSP-006's audio and levels guards (no changes under tools/audio/)

## Out of scope

- Re-implementing maxrects, the sort rule, atlas JSON, src/gen/assets.ts, asset-hashes.json or forge verify (SSP-010)
- The actor/item/fx transparent gutter, frame trimming, the fill-ratio report and the 2048 overflow error (SSP-113)
- Audio renderers or changes to the audio guards (SSP-006 guards; real renderers in M5)
- Real tile, facade and roof frames (SSP-040, SSP-041)
- Moving spike sprite lookups onto FRAME (SSP-018 already does this)
- forge verify changes or CI wiring (SSP-117)

## Acceptance criteria

- [ ] pytest: a fixture manifest with one `tile.*` entry (`atlas: world`) produces world.png and world.json; the 1 px ring around the frame duplicates its edge pixels, and the JSON rect {x, y, w, h} covers exactly the interior cell
- [ ] pytest: a fixture `facade.*` frame is extruded the same way, and a fixture actor frame in the same build is not extruded
- [ ] pytest: a fixture with no world entries emits no world.png or world.json
- [ ] pytest: packing the world fixture twice gives byte-identical PNG and JSON
- [ ] With the current repo manifest, `npm run assets && git status --short` prints nothing (actors/items outputs and src/gen/assets.ts are unchanged)
- [ ] `npm run assets` exits 0, `npm run audio` logs '0 sources', and the diff touches nothing under tools/audio/
- [ ] ASSET_PIPELINE §9.3 states the 1 px extrusion for ground tiles and facade modules, and that the JSON rect excludes the extruded border
- [ ] The lean_quadrants and scale_1440 visual goldens pass at threshold 0
- [ ] `uv run --project tools/forge pytest`, `npm run typecheck` and `npm run assets:verify` pass
