# SSP-005: Author kerbside32.json and forge OKLab palette mapping with a shared 4,096-sample fixture

**Milestone:** [M0 Foundations & Look Spike](../README.md#m0) · **Type:** feature · **Size:** M · **Areas:** assets, tooling, test · **Vertical slice**

## Summary

Create the palette file that every colour value comes from, plus the forge's deterministic OKLab nearest-colour mapper. Also generate a committed 4,096-sample RGB-to-index fixture that the TS nearest-colour function in SSP-016 must match exactly.

## Context

`assets-src/palette/kerbside32.json` is the truth for colour values. Copy ART_BIBLE §5.1 (index, name, hex). `name` is the snake_case identifier WITHOUT the table's parenthetical glosses: `ink`, not `ink (outline)`; `chalk`, not `chalk (white)`. rig.pal() looks entries up by these names (e.g. pal("lemon"), pal("sweeper_yellow"), pal("chalk"), pal("kerb")).
- 00 ink #0f0e12, 01 tar #24222a, 02 asphalt #3a3840, 03 asphalt_lt #55535a, 04 slab_dk #74727a, 05 slab #9a989c, 06 kerb #c3c1c0, 07 chalk #f2efe6
- 08 soot_brown #3b2421, 09 brick_dk #6b3a2c, 10 brick #9c5236, 11 terracotta #c97b4e, 12 skin_lt #e8b48a, 13 umber #8a5a3c, 14 ochre #c98a1a, 15 sweeper_yellow #f2c12e
- 16 lemon #fff27a, 17 hivis_orange #ff8a1e, 18 postbox_red #d23a2c, 19 maroon #8a1f27, 20 bubblegum #f07a8a, 21 hedge_dk #1f3a2a, 22 grass #2f6b3a, 23 grass_lt #5fa04a
- 24 lime #a8d06a, 25 navy #1c2b4a, 26 council_blue #2e5a9c, 27 sky #5ea0d8, 28 spray #a8dcef, 29 teal #2a8a86, 30 plum #4a2f6b, 31 lavender #8a5ab8

Ramps (§5.1): neutral 00→07; brick/skin 08→12; skin tones 12,11,13,08; yellow 14→16; orange/red 19→18→17; green 21→24; blue 25→28; purple 30→31; accents 20, 29. An index can belong to more than one ramp (e.g. 11 and 12).

File shape: `colors` (32 objects `{ name, hex }`, hex with a leading `#`, matching rig.pal()), `ramps` (object of name → index array), `night` (32 indices), `shadow` (32 indices), `swaps` (empty `{}` until M4).

night/shadow here are PROVISIONAL: identity, overlaid with the illustrative targets from ART_BIBLE §5.7.
- shadow: 02→01, 05→03, 06→04, 07→05, 10→09, 15→14, 23→22, 27→26.
- night: 02→01, 05→02, 07→04, 10→08, 15→14, 16→15, 23→21, 27→25.
The final tuning is SSP-021 (D-05/D-06). Mark them provisional in the PR.

Ramp-rule validator. The docs say "within its own ramp, or to the next ramp down" (ROADMAP) and "stay within its ramp or step to a darker ramp" (D-05). Proposed operationalisation (state it in the PR and use it in pytest): target == source; or target shares a ramp with the source and is not lighter in OKLab L; or target is in a different ramp and is strictly darker in OKLab L (ART_BIBLE §5.2 table).

`tools/forge/forge/palette.py`:
- load kerbside32.json;
- convert sRGB → linear → OKLab using Björn Ottosson's published matrices, in float64;
- nearest colour by squared OKLab distance, lower index wins an exact tie, no dither;
- a helper mapping an RGBA image to an index array (alpha < 128 → transparent).
No hex literals in palette.py.

Shared fixture (TECHNICAL_DESIGN §12.6: "generated by the forge and committed"):
- exactly 4,096 entries = the 32 palette colours + 4,064 RGB values from `numpy.random.Generator(PCG64(<fixed seed>))`; record the seed in the file;
- each entry is `[r, g, b, expected_index]`;
- suggested path `tests/fixtures/palette_oklab_4096.json` (readable by both pytest and Vitest; state it in the PR);
- generated by a forge entry point, e.g. `python -m forge.palette --write-fixture <path>`, which is deterministic and writes JSON with stable formatting.
Risk: JS Math.cbrt and numpy cbrt can differ by 1 ulp, which flips near-ties. If parity fails only on near-ties, quantise squared distances identically on both sides (e.g. round to 1e-12) and document it.

## Scope

- assets-src/palette/kerbside32.json (32 colours, ramps, provisional night/shadow, empty swaps)
- tools/forge/forge/palette.py (load, OKLab, nearest with lower-index tie-break, image → index array)
- Deterministic fixture generator + committed 4,096-sample fixture
- pytest: identity for all 32 colours, constructed exact tie → lower index, fixture regeneration byte-identical, ramp-rule validation of night/shadow

## Out of scope

- Final night/shadow tuning (SSP-021)
- The TS LUT (SSP-016)
- Swap tables (M4)

## Acceptance criteria

- [x] kerbside32.json has exactly 32 colours whose indices, snake_case names and hex values match ART_BIBLE §5.1 (names without parenthetical glosses)
- [x] Each palette hex maps to its own index via forge.palette
- [x] A constructed equidistant tie resolves to the lower index (unit test)
- [x] Regenerating the fixture twice yields byte-identical files, and it has exactly 4,096 entries including all 32 palette colours
- [x] A pytest validates every night[i] and shadow[i] against the stated ramp rule and fails on a deliberately bad entry
- [x] `grep -nE '#[0-9a-fA-F]{6}' tools/forge/forge/palette.py` prints nothing

## Verification

- python3 -c "import json;d=json.load(open('assets-src/palette/kerbside32.json'));assert len(d['colors'])==32 and len(d['night'])==32 and len(d['shadow'])==32"
- Regenerate the fixture, then git diff --exit-code tests/fixtures/
