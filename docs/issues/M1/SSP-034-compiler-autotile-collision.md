# SSP-034: Add kerb blob autotile, kerb edges, collision bits and merged solids to compiler

**Milestone:** [M1 Drivable Bessie](../README.md#m1) · **Type:** feature · **Size:** L · **Areas:** tooling, physics, test · **Vertical slice**

## Summary

Extend the level compiler with the 47-tile kerb blob autotile index, the KERB_EDGE and SOLID collide bits, merged solid rects (via the shared mergeSolids) and the path-distance validation rules. Commit the shared index↔neighbour-mask table that the forge kerb tile generator must also use.

## Context

Autotile (LEVEL_DESIGN §7.2, TECHNICAL_DESIGN §15.1 step 2):
- Per cell, a 47-tile kerb blob index 0..46 (255 = none), computed from road/non-road 8-neighbour adjacency. Authors only place ground chars.
- A dropped kerb `d` is pavement with no kerb edge toward the road; crossing it costs no speed.
- The canonical index ↔ 8-bit neighbour-mask table must exist exactly once and be read by both this TS compiler and the Python forge generator (SSP-040). Proposal: `assets-src/procedural/tiles/kerb_blob.json` → `params.blob_masks` (47 entries), with the rule 'corner bits count only when both adjacent edges are set'. ASSET_PIPELINE §10.8 already names `kerb_blob.json` as the rule-params file. The compiler reads it with fs (tools may use Node built-ins).

Collide layer (TECHNICAL_DESIGN §9.1), using the bit constants from `src/sim/map.ts`:
- SOLID: building cells, `w` low wall, `e` hedge, `r` railing, `~` water, `_` sand, void, and 1-tile alleys (footways, which LEVEL_DESIGN §7.3 marks non-drivable). Out-of-map is treated as solid by the runtime grid.
- KERB_EDGE_N/E/S/W: on the edges between a road cell and a raised-kerb pavement cell (both sides of the edge carry the bit for their direction). Dropped kerbs never get one.
- Static props (lamp post, bollard, bench, hydrant, tree, etc.) are NOT SOLID cells; they stay in `props` and become OBBs/circles in SSP-036.

Surface: already written by SSP-033. OPEN: the grip for `;` alley setts is not specified (§8.3 gives no grip). Proposal: pavement 8.0. Flag it and record it in LEVEL_DESIGN §8.3.

Merged solids: call `mergeSolids` from `src/sim/map.ts` and write `solids: [[x0, y0, x1, y1]]` in tiles.

Validation added (LEVEL_DESIGN §10.3). All path distances are BFS over drivable tiles, at 2 m per tile:
- L014: dead end longer than 6 tiles without a 5×5 turning head
- L015: a 1-tile alley mouth Bessie can enter (no bollard `!`, not bounded by buildings)
- L020: fewer than 2 depot bays; a skip within 40 m of a depot bay; a route tile more than 200 m from a dump site
- L021: a route tile more than 150 m from a hydrant or depot bay
- L022: a skip or hydrant with no stopping tile beside it

OPEN: §10.1 and §7.1 say markings (centre dashes, double yellows, zebras, bus boxes) are generated by the compiler and drawn by the procedural tile set, but compiled schema v1 has no markings layer. Decide: either the render derives markings from ground/width data, or a `markings` layer is added and TECHNICAL_DESIGN §15.2 updated in the same PR. Record the choice; SSP-045 and SSP-040 consume it.

## Scope

- Kerb blob autotile layer (0..46 / 255) and the shared mask table file, with a unit test that it has 47 unique entries and that every one of the 256 raw masks reduces to one of them
- collide layer SOLID and KERB_EDGE_N/E/S/W bits
- `solids` from mergeSolids
- L014, L015, L020, L021, L022 validation with failing fixtures
- A decision on the markings representation, recorded in docs
- Record the `;` grip decision in LEVEL_DESIGN §8.3

## Out of scope

- Generating the 47 tile images: SSP-040
- Prop collision footprints: SSP-036
- Lane graph / nav graph (M3)
- Runtime static collision resolution: SSP-036

## Acceptance criteria

- [ ] For a fixture covering straight kerbs, inner and outer corners, a road end and a dropped kerb, the autotile indices match hand-computed expectations
- [ ] A dropped-kerb cell has no KERB_EDGE bit toward the adjacent road; a raised kerb cell and its road neighbour both carry the matching bits
- [ ] Compiled `solids` cover exactly the SOLID cells of each fixture (no overlap, no gaps)
- [ ] Each new validation code has a failing fixture with the correct message format and a non-zero exit
- [ ] The kerb blob mask table is a single committed file that the compiler reads (no duplicated table in code)
- [ ] Compiling twice is still byte-identical
- [ ] The markings decision and the `;` grip are recorded in the owning docs
